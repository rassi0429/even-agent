# Agent進捗モニター（ローカル / Claude Codeクラウド）

現在の監視・画面生成は独立プロセス `apps/dashboard` が担当する。[構成](architecture.md)を参照。監視結果APIは3001番へ移動し、G2への配信は3000番の汎用APIを使う。

0.4.0ではアイコンと配置の生成をPC側へ移動した。クライアントは汎用scene描画で同じ進捗画面を表示する。[汎用画面API](screen-api.md)のcustomモードでは手動の画面が優先され、解除すると進捗表示へ戻る。以下の0.3.0の「内蔵アイコン」は旧版の説明。

2026-09-25実装。G2 Plugin 0.2.0と既存の項目API・画面配信プロトコルを使用する。このPCでは.envの `LOCAL_AGENT_MONITOR=1` により常駐サーバーで有効化済み。

## 表示

```text
Codex 実行 even-agent
Claude 稼働記録なし
```

1タスク1行。Agent名、状態、作業フォルダーの末尾名を表示する。会話タイトルには長いユーザープロンプトが含まれる場合があるため、初版ではフォルダー名を使う。同一Agent・同一フォルダーの複数タスクはID末尾4文字を添える。長い行は省略。

### 0.3.0のアイコン表示

クライアント0.3.0は、状態アイコン＋Agentのドット絵＋作業名の1行表示。Codexは結び目風、Claudeは放射状の18×18ピクセルのマーク。公式ロゴの厳密な複製ではなく、小さな単色表示用に単純化している。クラウド版は作業名の前に「雲」を添える。従来の文字列は0.2.0互換と画像エラー時の代替表示用に引き続き配信する。

実行中の8コマの回転はクライアント内で500msごと（送信完了後）に進める。PCの進捗更新ごとにアニメーションのフレームを配信しない。状態アイコンは回転 / ! / チェック / × / 一時停止 / 薄い輪。回転は進捗率ではなく、最後に取得した状態が実行中であることを表す。

8行・28px間隔、テキストコンテナー8個と画像コンテナー2個。左の48×112pxの帯を上下に置き、各帯に4行分のアイコンをまとめる。画像は4bitグレースケール。変化した帯のみを直列送信し、文字は内容変更時だけ更新する。更新待ちのフレームを積み上げない。メニュー中・終了後は送信停止、サーバー切断時は回転を薄い輪に置き換えてOFFLINEを表示する。

画像転送に失敗した場合は、次の描画再試行（通常3秒以内）で従来の文字画面へ切り替える。Pluginを開き直すとアイコンも再試行する。旧端末・ファームウェアの終了ダイアログ後の画像更新問題などは実機確認が必要。

現在の0.4.0向け画面は、上に日本時間の日付・曜日・時計（例: `2026/9/25 金 14:35`）、一番下に進捗行を表示する。稼働記録なしの行は非表示で、活動もエラーもなければ時計だけ。時計はPCが生成し、分の切替を1秒周期で検出して配信する。1ページ最大7行（時計用にtextコンテナー1個を確保）、複数ページの番号と切断時のOFFLINEは時計の下に表示する。画像の高さも行数に合わせて切り詰める。PC側のみの変更で、0.4.0クライアントの再インストールは不要。

| 表示           | 意味                                                             |
| -------------- | ---------------------------------------------------------------- |
| 実行           | CodexのinProgress、Claudeの直近ユーザー入力・処理中の記録など    |
| 確認待ち       | ClaudeのAskUserQuestionまたは明示的なwaiting記録                 |
| 応答完了       | Codexのcompleted、Claudeのend_turn等。依頼全体の成功保証ではない |
| 失敗           | Codexのfailed、Claudeのエラーresult                              |
| 停止           | Codexのinterrupted                                               |
| 更新なし       | 不明な状態、または3分以上新しい実行記録がない                    |
| 稼働記録なし   | 表示対象となる最近の記録がない。アプリ未起動とは限らない         |
| 取得できません | 読取失敗、または必要なCodex DBがない                             |

確認待ち・失敗を上に、実行中を次に表示。応答完了・停止は2分後に消し、その他も30分間更新がなければ除外する。長い無出力処理は「更新なし」になり得る。ファイルのmtimeだけで稼働を判定しない。

項目APIの登録内容は後ろへtitleを1行ずつ表示する。description / sectionなどの保存とAPI応答は維持。監視結果自体はitemsへ保存せず、メモリー上で画面に合成する。

## 取得方式と範囲

サーバー内で3秒ごとに読み、処理の重複を防ぐ。変化時に/ws/displayで全ページを配信。通常の15秒周期の配信も継続する。

### Codex

CODEX_HOME、未設定なら `~/.codex` のstate_5.sqliteとthread_history_1.sqliteをread-onlyで開く。最近の非アーカイブ・非サブエージェントの最大100タスクからID、cwd、最新ターンの状態、開始・完了・最終項目の時刻を取得する。会話本文、ツール引数・出力、思考内容は取得クエリに含めない。

内部DBは安定した公開APIではなく、このPCの現行形式に合わせたアダプター。形式変更時は読取エラーを表示する。Codexの承認・質問待ちは専用判定せず、inProgressの間は「実行」。同じDBへ記録しない古いCLIなどは対象外。

### Claude Code（CLI / デスクトップCode）

CLAUDE_CONFIG_DIR、未設定なら `~/.claude` のprojects内のメインセッション.jsonlを読む。デスクトップCodeもこの共通履歴へ記録される範囲を対象にする。subagents以下は除外。

最近書き込まれた最大100ファイルから各末尾256 KiBを読み、変更がなければ解析結果を再利用する。判定時刻はイベントのtimestamp。インポートなどでmtimeだけ新しくなった古い会話を稼働中として復活させない。巨大な単一行や欠けた記録は判定できない場合がある。

抽出するのはID、cwd末尾、時刻、イベント種別・stop_reasonとAskUserQuestionの有無。行はJSON解析のためメモリー内で読むが、本文・ツール引数・思考内容をG2、API、ログ、サーバーDBへ転送・保存しない。

sessions/*.jsonに最近の明示的状態がある場合はPIDの存在も確認して併用する。新規起動直後にも存在するidleだけでは応答完了と判定しない。すべての権限ダイアログを検知できるわけではない。

### Claude Cowork

WindowsのAPPDATA/ClaudeとStore版LOCALAPPDATA/Packages/Claude_*/LocalCache/Roaming/Claudeを探索。その中の `local-agent-mode-sessions/<account>/<org>/local_*/.claude/projects` にホスト側履歴があるセッションを同じ方法で読む。

VMディスクやクラウドにしか履歴がないCoworkは取得できない。通常のClaudeチャットは対象外。このPCでホスト側の履歴形式は確認したが、今回進行中のClaude作業はなく、新しい実作業での検証は未実施。

### Claude Codeクラウド（試験対応）

`LOCAL_AGENT_MONITOR=1` と `CLAUDE_CLOUD_MONITOR=1` で有効。このPCでは両方有効化済み。G2パッケージの更新は不要。

```text
Claude雲 実行 launcher
Claude雲 確認待ち launcher
Claude雲 応答完了 launcher
```

Claude CLI 2.1.269が使用する内部API `GET https://api.anthropic.com/v1/code/sessions?limit=100` から最近の最大100セッションのメタデータを30秒ごとに取得する。安定した外部向け公開APIではないため、将来の変更で取得できなくなる可能性がある。100件より古いセッションは対象外。

`environment_kind=anthropic_cloud` だけを対象とし、ローカルを中継するbridgeやアーカイブ済みを除外する。worker_statusのrunning / requires_action / idleを実行 / 確認待ち / 応答完了へ対応させる。idleは現在処理していない状態であり、作業全体の成功は保証しない。未知の状態は更新なし。会話タイトルではなくリポジトリー名を表示する。

完了・停止・失敗は最終イベントから2分間表示する。取得に成功した実行中・確認待ちは、イベント時刻が古くても現在の状態として表示する。ローカルの3分無更新ルールは適用しない。初回取得時点ですでに2分以上前に終わった作業は表示しない。30秒の取得間隔の間に開始・終了した短い作業では、実行中表示を見逃すことがある。

既存のClaude CLIログインを利用し、CLAUDE_CONFIG_DIRまたは `~/.claude/.credentials.json` のアクセストークンを毎回読み直す。送信先は固定のAnthropic HTTPS APIで、リダイレクトしない。認証情報・会話本文・API応答の全文をサーバーログ、DB、G2、診断APIへ保存・転送しない。トークン更新や認証ファイルの書換えは行わず、Claude CLIに任せる。

認証期限切れ・401/403では `Claude雲 認証更新が必要` と表示する。PC上のClaude CLIを起動して認証を更新し、ログインを求められた場合はログインする。監視側は30秒ごとの再読取で自動復帰する。Claude CLIを長期間使わない場合、常時監視は認証期限で止まることがある。

通信失敗・形式変更では `Claude雲 取得できません` とし、前回の実行中表示を消す。通信待ちは最大10秒。429では5分待って再試行する。クラウド通信はバックグラウンドで行い、ローカルの3秒周期を待たせない。sources.claudeCloudはchecking / ok / auth-required / rate-limited / read-error。

実アカウントから、スクリーンショットのlauncherクラウドセッション（idle）を取得できたことを確認済み。クラウドの実行中→確認待ち→完了の実作業による連続確認は未実施。自動テストでは状態対応、重複除外、期限・失敗・レート制限、ローカル取得との分離を検証する。

### 公式フックとの関係

[OpenAI公式Hooks](https://learn.chatgpt.com/docs/hooks) と [Claude Code公式Hooks](https://code.claude.com/docs/en/hooks) も調査。今回は既存作業を再起動・再設定せず試せる読み取り方式とした。フックのインストールや信頼設定の変更は行っていない。内部形式への依存はagents.tsに分離している。

## 診断と停止

```powershell
Invoke-RestMethod http://127.0.0.1:3001/api/agents | ConvertTo-Json -Depth 5
Invoke-RestMethod http://127.0.0.1:3000/health | ConvertTo-Json -Depth 5
(Invoke-RestMethod http://127.0.0.1:3000/api/display).pages
```

/api/agentsはtasks、sources、observedAtを返す。tasksの要素はid / agent / surface / project / status / updatedAt。絶対パスと会話本文は含まない。sourcesのokは読取処理の成功を表し、すべての実行形態を観測できる保証ではない。表示アプリの :3001/health.agentMonitorにも読取状態と件数を追加。

この読取APIも認証なしで、信頼するtailnet内で使用する。作業フォルダー名・クラウドのリポジトリー名は接続先へ表示する。監視はサーバープロセス内で行い、別タスクの追加はない。CodexやClaudeの設定・権限は変更しない。

停止するには.envのLOCAL_AGENT_MONITORを0にし、`pnpm dashboard:restart` で再起動。従来の時計・カテゴリ表示へ戻る。G2パッケージの再インストールは不要。

以前の「接続テスト成功」項目は今回削除し、.local/previous-demo-item.jsonへ退避済み。

### 時計下の全幅ガイド（2026-09-25）

ヘッダー下に576px幅・1pxの横線を追加。通常y=34、ページ番号/OFFLINEのあるヘッダーではその下のy=62。288×20pxの静止画像2枚で描き、7行時でもtext8/image4の上限内。PC側のみの変更で0.4.0以降の汎用クライアントへ反映する。

文字領域は左右4pxを引いて568px。公式 @evenrealities/pretext 0.1.4で `2026/9/25 金 14:47   G2 70%` は252px、残り316pxと計算された。区切りの空白を1つ入れた後、日本語「あ」なら15文字、数字「0」なら25文字が目安。時計のみでは残り396pxで、日本語19文字/数字32文字。実際の文字の組み合わせやファームウェアで差が出る。測定用パッケージは.local/font-measureに隔離し、アプリの依存には追加していない。

### 横並び・折り返し（2026-09-25）

最新のscene表示では、状態アイコン＋Agentアイコン＋作業名をまとまりとして左から右へ並べる。公式 @evenrealities/pretext 0.1.4で文字幅を測り、項目間20pxを確保する。入りきらない項目を次行へ丸ごと送り、まとまり全体を画面下へ寄せる。1行ならy=260、2行ならy=232/260。

1ページ最大7項目（時計込みtext8）、最大5段（画像の高さ140px）を超えたら次ページ。横長アイコン画像を左右2領域以内にまとめ、実際に絵がある横幅に切り詰める。ヘッダー横線2枚と合わせてimage4以内。長すぎる名前はピクセル幅で省略し、同名タスクのID末尾は残す。文字コンテナーは次のアイコンの直前まで広げる。汎用scene対応の0.4.0以降へPC側の変更だけで反映し、旧版向けテキスト代替は従来の縦並びを維持する。
