## 指定サービスのヘルス監視

`apps/dashboard/src/health-monitor.ts` がNebiとは独立して、本人の選んだ最大4つの読取専用health URLを監視する。ルートの無視対象 `.env` にJSON配列で設定する（以下のHOST/PORTは実際の監視先へ置き換える）。現時点の常用設定は空で、監視対象は本人へ確認中。

```dotenv
SERVER_HEALTH_TARGETS='[{"id":"home","name":"自宅サーバー","url":"http://HOST:PORT/health","expectedStatus":200}]'
```

`id` は英小文字・数字・ハイフン、`name` は表示名で最大12文字。`expectedStatus` は省略時200、指定できるのは2xx。HTTP/HTTPSのGETだけで、URL認証情報・query・fragmentは拒否する。リダイレクトせず、Cookieや認証キーを付けず、応答本文も読まない。認証付き監視や本文の意味判定はこの実装の対象外。取得URLはLLMやブラウザから指定できず、ローカル設定だけで変更する。

- 30秒ごと、最大3秒のtimeout。重なった呼出は同じ試行を待つ。
- 3回連続失敗で中央に表示。接続不能とHTTPステータスを分け、停止原因は断定しない。
- 2回連続成功で表示を消去。成功1回目は「復旧を確認中」。
- 最後の完了した確認から90秒経過したら「監視の更新停止」。観測の空白期間は連続回数をリセットする。
- 健全なら何も出さない。警告が出ている間はNebiの通常情報より上に置き、2行に収まらない時は「ほかあり」を添える。
- 状態はメモリ内。dashboardを再起動すると未確認から再取得する。設定が不正ならその旨を表示し、設定本文は出さない。

`pnpm dashboard:restart` で反映する。G2クライアントの更新は不要。`/health` の `monitoring` は対象ID・表示名・状態・最終確認時刻・HTTPコードだけを返し、URLや本文を返さない。dashboard自身のhealthコードは従来通り配信接続を表す。監視対象の異常は `monitoring.targets` で確認する。

Nebiを使わず監視だけを設定しても、同じ1ページの中央へ出す。監視もNebiも無効なら従来のAgent表示へ戻る。手動カスタム画面は上書きしない。dashboardと同じPC全体が止まった場合はこの監視も止まるため、別ホスト監視または端末の接続断表示が必要。
